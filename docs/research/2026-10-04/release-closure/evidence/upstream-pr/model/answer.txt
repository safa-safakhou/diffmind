## Review finding

**Request changes:** the duplicate username path still raises an unhandled error. In [auth.py](<HANDLER_TRIAL>/upstream-flask/examples/tutorial/flaskr/auth.py:70), the handler catches `db.IntegrityError`, but `db` is the SQLite connection returned by `sqlite3.connect()` in [db.py](<HANDLER_TRIAL>/upstream-flask/examples/tutorial/flaskr/db.py:12). `IntegrityError` is the module-level `sqlite3.IntegrityError` exception. When SQLite raises it, looking up `db.IntegrityError` fails, so the intended flashed validation error is not shown. [Python’s sqlite3 documentation](https://docs.python.org/3.11/library/sqlite3.html) lists `IntegrityError` as an exception in the `sqlite3` module. The catch should use `sqlite3.IntegrityError` (with `sqlite3` imported in `auth.py`); the tutorial text in `docs/tutorial/views.rst` should match.
